Writing blog posts in Typst

2026-10-30

My site generator started out with only my own Markdown parser. It’s great for writing prose, but as soon as a post needs an equation, Markdown falls apart. So the generator can now also build posts written in Typst, a modern alternative to LaTeX. This post is itself a .typ file!

How it works

Typst can export HTML (it’s still experimental), so the generator calls the Typst compiler through the Process module, the same way it already calls Bun to highlight the code blocks. Each post is compiled through a small wrapper file that sets up a few show rules for the website, then includes the post:

#show raw.where(block: true): it => html.elem(
  "pre",
  html.elem("code", attrs: (data-lang: if it.lang == none { "" } else { it.lang }), it.text),
)

#include sys.inputs.path

The generator then takes the content of the <body>, and gives the code blocks to highlight.js, so they look exactly like the ones of the Markdown posts. The frontmatter is a block comment at the top of the file with the same key: value lines as the Markdown posts, so Typst simply ignores it. A post looks like this:

/*
title: Writing blog posts in Typst
slug: writing-posts-in-typst
pub_date_time: 2026-10-30
*/

= Equations

Typst exports equations like $F_0 = ((n_1 - n_2) / (n_1 + n_2))^2$ as MathML, which means:
- No JavaScript, the browser renders them natively
- They can be selected and copied like the `rest` of the text

See the #link("https://typst.app/docs/")[documentation]

Equations

The main reason to use Typst is the math. Typst exports equations as MathML1 MathML Core has been supported by all the major browsers since Chrome added it in 2023., so the browser renders them natively, without any JavaScript. Inline math like 𝑓0=(𝑛1−𝑛2𝑛1+𝑛2)2 sits right inside the text, and block equations get their own line, like the rendering equation:

𝐿𝑜(𝑥,𝜔𝑜)=𝐿𝑒(𝑥,𝜔𝑜)+∫Ω𝑓𝑟(𝑥,𝜔𝑖,𝜔𝑜)𝐿𝑖(𝑥,𝜔𝑖)(𝜔𝑖⋅𝑛)d𝜔𝑖

For example, here is Schlick’s approximation of the Fresnel term, which I used in my PBR renderer:

𝐹(𝜃)=𝐹0+(1−𝐹0)(1−cos𝜃)5

And here it is in GLSL:

// Schlick's approximation, f0 is the reflectance at normal incidence
vec3 fresnelSchlick(float cosTheta, vec3 f0)
{
    return f0 + (1.0 - f0) * pow(clamp(1.0 - cosTheta, 0.0, 1.0), 5.0);
}

Scripting
